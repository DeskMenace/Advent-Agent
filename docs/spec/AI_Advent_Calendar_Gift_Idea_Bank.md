# AI Advent Calendar — Provisional Gift Idea Bank

> **Status: Unselected brainstorming backlog, not a finalized product scope.**
> Compiled 7 November 2026 from the ideas discussed. Similar items are intentionally preserved where they suggest different executions; obvious exact duplicates are folded into richer entries. No prioritization or commitment is implied.

## Foundation

- **Agent-agnostic and person-agnostic.** The calendar must not assume the user codes, runs a startup, lives alone, celebrates Christmas, has a pet, or shares any specific hobby. Every contextual idea is conditional, not the default.
- **The agent chooses and makes the gift.** The catalog is an inspiration bank, not a rigid decision system or queue. The agent may modify, combine, reject, or invent new ideas.
- **Gift-ready delivery.** A game must work; a song must play; a visual should be delivered at useful resolution; a purchase suggestion should include an actual product/vendor and a verified path to buy; an experience should provide a real itinerary/booking path. Never imply a gift was bought unless it was actually bought.
- **User buys physical goods or experiences.** The agent may research, design, compare, and prefill forms where authorized, but no automatic spending or payment.
- **Personalization is opt-in and context-sensitive.** Use what the connected agent legitimately knows and is permitted to access; don't invent memories. A delightful universal gift is better than a forced personal reference.
- **Budget-aware and portable.** The user sets a per-gift token budget. Provider and external media costs are tracked separately. Distinguish hard spending caps from advisory token preferences if the agent platform cannot expose exact consumption.
- **Capabilities vary.** Each agent may have different tools, memory, skill support and scheduling. Everything beyond a simple artifact is an optional enhancement.

## Gift recipe structure — suggested metadata, not final schema

```yaml
id: optional-stable-id
title: example gift idea
summary: one-sentence concept
suitable_if: context or preferences this idea actually requires
avoid_if: possible mismatches, unwanted jokes, age constraints, etc.
deliverable: html | image | audio | video | text | pdf | printable | product-proposal | experience-proposal
minimum_done: what must exist for the present to be genuinely gift-ready
personalization_hooks: optional clues the agent can use when permitted
cost_profile:
  agent_tokens: estimate only
  external_generation: free | user-key | paid | none
  purchases: user-only
capability_requirements: optional tools or skills, not hard dependencies
quality_checks: how to test/open/verify the result
example_variations: illustrative, never exhaustive
```

## Creative guidance for the gifting agent (optional, not strict rules)

- Vary tone and medium when that will improve surprise; a series or deliberate repetition may be better than forced variety.
- Consider making seasonal gifts optional: some gifts can be completely unrelated to winter or Christmas.
- Prefer one complete modest gift to an ambitious broken artifact.
- Reuse established jokes and references only when appropriate; don't infer sensitive or unshared context.
- Where useful, remember earlier gifts to enable callbacks, collectible sets and long-running surprises.
- Optional larger finale, no two similar gifts in a row, weekly wildcards, weekend special builds and 7am reveal are **examples**, not requirements.
- Agent can draft the gift the night before in scheduled mode; run on-demand for agents without autonomous scheduling; or accept the artifact generated externally by a noncoding agent.
- The calendar is a delivery and display layer; it should not have to be the agent's memory or creative engine.

## Example completeness standards

- **Mini-game:** an actual playable self-contained artifact, tested for load, interaction, and basic responsiveness.
- **Song:** audible original track or truly functioning generative melody; lyrics alone are not a finished song if audio was promised.
- **Image/print:** actual artwork in usable dimensions, and production file if fabrication is proposed.
- **Enamel pin:** finished artwork/mockup, manufacturing format and sensible size, a feasible real supplier, quantity/minimum-order and estimated cost, and a purchase/customization path. If a ready-filled checkout isn't technically possible, say what remains for the user to do.
- **Mountain hut:** a specific suitable hut and route; season/access/safety and travel assumptions; live pricing and reservation link when verifiable; clear note that booking/payment remain with the human.
- **Book or purchased gift:** exact item and a working purchase link, plus price and shipping/availability caveats if obtainable.
- **IOU:** only promise capabilities the connected agent can actually perform in future, subject to authorization and tool availability.

## Potential creative tooling — researched options (November 2026)

- **Suno:** official Suno Platform advertises a REST API (https://platform.suno.com/) and Suno MCP (beta) exists for supported AI assistants (https://help.suno.com/en/articles/14486145). Provider credentials, quotas, licensing and platform eligibility require validation before integration.
- **ACE-Step 1.5:** MIT-licensed open model for full music generation; local REST API supported, but model files and GPU/CPU resource requirements make it an optional self-hosted path, not a lightweight default for all browsers. https://github.com/ace-step/ACE-Step-1.5
- **Basic browser audio:** Web Audio API can synthesize original chimes, music box motifs and sound effects without a third-party generation key, but is not equivalent to full studio-quality vocal music. https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API
- **/brag:** open-source skill to make a launch video from a project (https://github.com/latent-spaces/brag); narrower than a general gift-video generator, but useful as an optional skill or inspiration for a generic video gift skill.
- **MusicGen:** code MIT, weights CC BY-NC 4.0; not a straightforward default for a commercial hosted product. https://github.com/facebookresearch/audiocraft

## Portable agent-connection proposal (exploratory)

A small **gift submission contract** could accept an artifact and preview from any compatible agent: `calendar_id`, `door_date`, `type`, `artifact_location` or uploaded file, optional `message`, optional `vendor/booking` links, `costs` and `reveal_at`. Integrations might be agent skill/MCP tool, REST/webhook, or manual export/upload. A platform with only chat output may need explicit user action; not all assistants permit autonomous tasks or third-party skill installation.

User-facing permissions might be tiered: (1) read approved context, (2) create gift artifacts, (3) search public web, (4) call authorized creative APIs, (5) prepare merchant forms for review. Payments and irreversible actions are never part of automatic gifting. Secure provider keys server-side or in the user's agent secret store rather than in a public calendar web page.

## Open questions (intentionally unresolved)

- How open should third-party agents be: official skill, MCP, webhook, import-only, or all of these?
- How many recipe ideas should ship initially, if any? Should the agent know the entire library or retrieve a shortlist?
- How to enforce hard token limits for agents that don't expose token telemetry or billing?
- What happens when an agent lacks web access, local execution, image generation or scheduling?
- Should a present be a standalone gift or can it be a staged suggestion requiring user action?
- What must a physical product vendor support before we classify a gift as truly purchase-ready?
- How to make a gift shareable without leaking private source context or secrets?
