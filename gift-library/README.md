# Gift idea library

A library of gift ideas for the agent that makes the presents behind the 24 doors. It was converted from the project's idea bank (78 ideas in groups A–H) and stays open: anyone can add, edit or remove an idea through a normal pull request.

**Ideas are inspiration, never a quota.** The agent chooses and makes the gift. It may combine ideas, change them or ignore this library entirely. Nothing in the code selects, rotates or counts them.

**The agent never purchases or books.** Ideas marked `real_world: suggest` end in a proposal: a verified item, vendor, price with the date it was checked and "what is left for you to do". The recipient buys or books.

## Layout

- `ideas/<id>.md`: one file per idea, YAML frontmatter plus free-form notes (one "Great:" and one "Lazy:" example and a pitfall).
- `INDEX.json`, `INDEX.md`: generated by `npm run library:index`. Do not edit by hand; CI fails when they are stale.

## Format

```markdown
---
id: museum-of-abandoned-ideas          # kebab-case, equals the file name
title: The Museum of Abandoned Ideas
group: A                               # A–H, see INDEX.md for the group names
summary: One sentence.
suitable_if: The context this idea actually requires (e.g. "developer-context only").
avoid_if: Mismatches, sensitive topics, missing context.
forms: [interactive-html, printable-card]      # concrete output forms
minimum_done: What must exist for the present to be genuinely gift-ready.
personalization_hooks: [abandoned projects, old hobbies]
skills: [storyteller, art-studio]      # workshop skills: gift-director, storyteller, arcade, art-studio, sound-studio, maker, concierge, quality-and-packaging
effort: medium                         # low | medium | high (token band hint only)
real_world: none                       # none | suggest (agent never purchases)
quality_checks: [opens, content-complete, no-private-info]
variations:
  - A printed-style exhibition catalogue
status: candidate                      # candidate | approved
---
Free-form notes. Great: … Lazy: … Pitfall: …
```

The schema is `IdeaFrontmatterSchema` in `src/shared/idea.ts`. Quality checks come from a small vocabulary: `opens`, `content-complete`, `no-private-info`, `no-invented-facts`, `interaction-works`, `audio-plays`, `print-sizes-correct`, `links-verified`, `price-date-checked`, `no-purchase-claim`.

## Adding an idea

1. Copy an existing file in `ideas/` to `ideas/<new-id>.md` and edit it. Keep the id kebab-case and equal to the file name.
2. Run `npm run library:index` to regenerate `INDEX.json` and `INDEX.md`.
3. Run `npx vitest run test/unit/library.test.ts`.
4. Open a pull request. See `CONTRIBUTING.md` at the repo root.

## Status

- `candidate`: in the library, usable by any agent, not yet reviewed in the gift lab.
- `approved`: reviewed and approved by the maintainer after a gift-lab run (TEST_PLAN §6). Status only matters for the review workflow and the README showcase; agents may use any idea regardless of status.
